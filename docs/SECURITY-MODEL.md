# Модель безопасности Jarvis: что защищено, от кого и чем (финальный аудит)

Всё ниже — состояние кода ветки `dev/punkt-9-11-13`; «подтверждено CI» означает прогон на Windows (раннер GitHub), «не проверено» — требует реального ПК.

## 1. Токен окна (порты 9714 и 9712)
Где: файл `ui_token` в папке данных `%APPDATA%\com.priler.jarvis`, 256 случайных бит. Окно получает его в адресе после `#` (не уходит по сети), страница держит его в памяти вкладки и добавляет к каждому запросу. Сравнение за постоянное время; без токена — 403. Открыты только страница и значок.

| Кто пытается | Результат |
|---|---|
| Веб-страница в браузере (DNS rebinding, чужая вкладка) | остановлена проверкой `Host`/`Origin` **и** токеном |
| Другая учётная запись Windows | папка данных закрыта защищённым списком доступа (SYSTEM, администраторы, владелец) — **подтверждено CI** (`DATA ACL`) |
| Программа того же пользователя | **не остановлена**: она владелец папки, читает файл токена и память Jarvis, и может подменить любые файлы пользователя |
| Администратор, SYSTEM | не останавливаются |
| Резервная копия / сетевой диск, следующие за наследованием прав | остановлены тем, что у папки свой защищённый список без наследования |

Что НЕ утверждается: что токен защищает от процесса с теми же правами Windows. Он защищает от всего остального на этом ПК. Токен не попадает в журнал (`sanitize`), не хранится в истории браузера (фрагмент адреса), удаляется деинсталлятором.
Более безопасный механизм «в рамках архитектуры» отсутствует: любой секрет, который читает окно Jarvis, читает и другой процесс того же пользователя; настоящее разделение дали бы отдельная учётная запись или изоляция процесса (не входит в текущую версию).

## 2. Собственные файлы программы: запись
Папка данных закрыта для других пользователей (ACL). Остальное — способ записи:

| Путь | Кто пишет | Способ записи | Остаточный риск |
|---|---|---|---|
| `ui_settings.json`, `app.db`, `telegram.json`, `scenarios.json`, `timers.json`, `apps_index.json`, `tts_off`, `avatar.img`, кэши намерений, чаты и архив, `active` | программа | `write_atomic`: временный файл `create_new`, перенос поверх имени; ссылка под временным именем не пишется насквозь, ссылка на месте цели заменяется | процесс того же пользователя |
| `ui_token`, `remote_token` | программа | `write_atomic` + права (Unix 0600; Windows — права папки) | то же |
| `cloudflared.exe.part`, `*.part` голоса, Piper `.zip`, проба записи | программа | `create_fresh` (старый файл/ссылка убираются, `create_new`), хеш/форма проверяется **до** переименования | то же |
| DLL микрофона во временной папке | программа | `ensure_file`: SHA-256, `create_new`, перенос | то же; зависимые DLL ищутся рядом с программой |
| Файлы пользователя по командам Lua | команды | **`safefs`** (проверка места удерживаемой папки дважды) | см. `src/safefs.rs` |
| `.state.json` пака, перенос из старого места (`fs::copy`) | команды/программа | `write_atomic`; перенос копирует один раз | копирование идёт по ссылке в папке пака (папка программы закрыта правами) |
| Отчёт `--selftest-speech <файл>` | CI | `fs::write` по пути из аргумента командной строки | путь задаёт тот, кто запускает программу; для команд недоступно |
| Журнал | библиотека журнала | свои средства библиотеки | то же |

Через `safefs` не идут и не должны: собственные файлы программы с фиксированными путями — путь не задаётся ни командой, ни фразой; их переносить на `safefs` значило бы удерживать папку на каждую запись без выигрыша против процесса того же пользователя.

## 4. `jarvis-gui`
Входит в рабочее пространство (`Cargo.toml`), **не входит в поставку**: CI собирает `-p jarvis-app`, установщик кладёт только `jarvis-app.exe` и библиотеки. Но «Настройки» в трее `jarvis-app` запускает `jarvis-gui.exe` из своей папки, если он там лежит (`tray.rs`); без него — запись об ошибке в журнале. Папка программы закрыта от записи другим пользователям (установщик), поэтому подложить `jarvis-gui.exe` может только владелец. Его команда `show_in_folder` теперь принимает только полный существующий путь. Сборка проверяется заданием `gui-check` в CI (информационное, не блокирует). Удалять крейт нельзя без отдельного решения.

## 5. Установщик и режимы
| Режим | Папка | Права после установки | Голос Piper |
|---|---|---|---|
| Для текущего пользователя (по умолчанию, `%LOCALAPPDATA%\Programs\Jarvis`) | в профиле | только пользователь, SYSTEM, администраторы | «Установить голос» работает, пишет в папку программы |
| Любая другая папка, установка обычным пользователем | вне профиля | владелец — изменение; SYSTEM, администраторы — полный; остальные пользователи — чтение и запуск | работает для владельца |
| Любая другая папка, установка администратором, работа обычным пользователем | вне профиля | обычный пользователь **не** может писать | «Установить голос» объясняет, что нет прав записи, и советует большой установщик; **голос в этом режиме надо ставить большим установщиком** |
| Большой установщик (Piper внутри) | любая | как выше | не требуется |
Подтверждено CI (прогон 557aa0d): установка в папку с кириллицей и пробелом, обновление поверх запущенной программы, деинсталляция, права папки (`INSTALL FOLDER ACL`). Установка голоса из самой программы (скачивание, SHA-256 и имена архива, распаковка через `psrun`) проверяется заданием `VOICE INSTALL E2E`, добавленным после этого прогона: его результат указан в отчёте, а не здесь.

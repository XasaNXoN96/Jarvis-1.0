# Проверка Jarvis User на настоящем Windows (руками, по шагам)

Что реально проверено на настоящем Windows до сих пор: **только сборка и установка в CI** (установка Jarvis Admin в папку с кириллицей, удаление, запуск без падения). Jarvis User в CI **собирается, проходит тесты и проверку секретов, упаковывается**, но **не запускается**. Всё ниже — проверка для вас.

## Подготовка
1. Нужен работающий сервер лицензий (см. `DEPLOYMENT.md`) **или** локальный: на этом же компьютере `jarvis-license-server serve` на `127.0.0.1:8787` (клиент разрешает `http://127.0.0.1` для проверки).
2. Соберите User с адресом и открытым ключом (`DEPLOYMENT.md`, раздел 4) — готовый CI-установщик без этих значений активироваться не сможет (это нормально и входит в проверку, шаг 3).
3. Установщик: GitHub → Actions → запуск 38790362792 (или новее) → Artifacts → **`jarvis-user-installer`** → внутри `Jarvis-User-Setup.exe`. Устанавливается в `%LOCALAPPDATA%\Programs\Jarvis User` и не затрагивает обычный Jarvis.

## Сценарии (отмечайте ✅/❌ и присылайте результат)
| № | Действие | Ожидается |
|---|---|---|
| 1 | Установить и запустить Jarvis User | Окно открывается, в шапке плашка **Demo**; нет пункта меню «Лицензии» |
| 2 | Сказать/написать бесплатную команду («который час», «погода») | Работает |
| 3 | Платная команда («открой Word», «найди файл…») | Окно «Эта функция доступна в Jarvis Premium…» с кнопками «Активировать Premium» / «Позже»; команда **не** выполняется ни сразу, ни после активации |
| 4 | Нажать «Позже» | Окно закрывается, ничего не запускается |
| 5 | Отключить интернет → «Активировать» с настоящим ключом | Сообщение «Нет связи с сервером…», плашка остаётся **Demo** |
| 6 | Включить интернет → ввести **неверный** ключ | «Ключ не найден…» |
| 7 | Ввести настоящий ключ | «Готово…», плашка **Premium · N дн.**, платные команды работают |
| 8 | Тот же ключ на **втором** компьютере/установке | Отказ «уже активирован на другом компьютере» |
| 9 | Закрыть и снова открыть программу | Premium сохранился |
| 10 | Выключить интернет на 1 день → запуск | Premium работает (срок без сети 72 часа) |
| 11 | В админке «Отозвать» лицензию → ждать до 6 часов или перезапуск с интернетом | Плашка возвращается к **Demo** |
| 12 | Закончить подписку: создайте ключ с самым коротким сроком (7 дней) и дождитесь конца, либо на тестовом сервере сдвиньте дату базы | Окно «Ваша подписка Jarvis Premium закончилась…» с «Да, продлить» / «Нет, выйти» |
| 13 | «Да, продлить» | Тарифы с сервера ($5 / $25 / $50 / Lifetime), поле для **ключа продления**, честная пометка, что оплаты в программе нет |
| 14 | Ввести ключ продления | Срок добавился к текущему концу; повторный ввод того же ключа ничего не меняет |
| 15 | «Нет, выйти» или крестик окна | Программа закрывается |
| 16 | Руками изменить `license.json` в `%APPDATA%\…` (дата «floor», токен) | Файл не принимается, программа Demo; Premium не появляется |
| 17 | Установить рядом **Jarvis Admin** (обычный `Jarvis-Setup`) | Видна страница «Лицензии», доступны Keygen, список, тарифы, журнал; Admin выполняет всё без ключа |
| 18 | Пульт с телефона: платная команда в Demo | Отказ с тем же текстом, команда не выполняется |
| 19 | Telegram (если настроен): платная команда | То же |
| 20 | Сказать «создай python файл» (работа с кодом) в Demo | Отказ Premium |

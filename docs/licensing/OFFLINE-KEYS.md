# Офлайн-ключи: Premium без сервера лицензий

Ключ выдаёт владелец вручную для **одного** компьютера. Программа проверяет его сама: подпись, компьютер, срок. Сервер не нужен.

## Как выдать ключ
1. Покупатель открывает окно активации в Jarvis User. Там написан **код этого компьютера** (43 знака, кнопка «Копировать») и присылает его вам.
2. На вашем компьютере (с файлом секретного ключа подписи `JARVIS_LS_SIGNING_KEY_FILE`, тем же, чей публичный ключ вшит в сборку как `JARVIS_LICENSE_PUBKEY`):

   ```
   jarvis-license-server offline-sign <код-компьютера> <название-тарифа> <срок> [журнал]
   ```
   Срок: `30d` (дни), `6m` (месяцы), `life` (навсегда). Пример:
   `jarvis-license-server offline-sign epM4cBhO… MONTHLY 30d выдано.log`
3. Команда печатает длинный ключ (около 350 знаков). Пришлите его покупателю. В `выдано.log` остаётся строка: время, номер ключа (`OFF-…`), тариф, срок, код компьютера.
4. Покупатель вставляет ключ в то же окно активации. Интернет не нужен.

Для сборки нужен только публичный ключ (`JARVIS_LICENSE_PUBKEY`); адрес сервера (`JARVIS_LICENSE_URL`) для офлайн-ключей не нужен.

## Почему ключ нельзя использовать повторно на другом компьютере
- Код компьютера **внутри подписанного ключа**. Другой компьютер имеет другой код, программа там ключ отклонит («выдан для другого компьютера»).
- Код делается из пары ключей установки: её секретная часть хранится под защитой Windows (DPAPI) этого пользователя и этого компьютера. Файл настроек, скопированный на другой компьютер, не расшифруется.
- Подделать или изменить ключ (срок, тариф, компьютер) нельзя без вашего секретного ключа: подпись перестанет подходить.
- Срок закончился: ключ не продлить без новой подписи. Защита от перевода часов назад работает и здесь.

## Что остаётся слабым местом (честно)
- **Отозвать ключ нельзя.** Он действует до конца срока. Поэтому выдавайте короткие сроки, если нет доверия.
- **Тот же покупатель на том же компьютере** может вводить ключ сколько угодно раз: это его ключ.
- **Переустановка Windows или смена компьютера** меняет код: нужен новый ключ (проверьте по журналу выдачи, чей это код).
- **Утечка секретного ключа подписи** позволяет кому угодно выпускать ключи. Храните файл офлайн, делайте копию, не кладите в репозиторий. Тот же ключ защищает и серверные лицензии, если вы ими тоже пользуетесь.
- Ведите журнал (`[журнал]`): это единственный список выданного.

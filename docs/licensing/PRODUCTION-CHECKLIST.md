# Что нужно для production License Server (список для владельца)

Статус по каждому пункту: **НЕТ** = ещё не сделано, ничего не развёрнуто и не выдумано. Команды и значения — в `DEPLOYMENT.md` и `deploy/license-server.env.example`.

| № | Что | Статус | Как проверить, что готово |
|---|---|---|---|
| 1 | Сервер (VPS/хост) с Linux, доступ по SSH, только вы | НЕТ | `ssh …` |
| 2 | Домен и DNS-запись на этот сервер, например `license.<ваш-домен>` | НЕТ | `nslookup license.<домен>` |
| 3 | HTTPS через обратный прокси (Caddy/nginx), сертификат Let's Encrypt | НЕТ | `curl https://license.<домен>/health` → `{"ok":true,…}` |
| 4 | Сборка `jarvis-license-server`, служба systemd под отдельным пользователем | НЕТ | `systemctl status jarvis-license` |
| 5 | Каталоги с правами 700, файл настроек 600 (`/etc/jarvis-license/server.env`) | НЕТ | `ls -l` |
| 6 | Переменные: `JARVIS_LS_DB`, `JARVIS_LS_SIGNING_KEY_FILE`, `JARVIS_LS_PEPPER_FILE` (обязательны); `JARVIS_LS_BIND`, `JARVIS_LS_CLIENT_IP_HEADER`, `JARVIS_LS_GRACE_HOURS` (72), `JARVIS_LS_ACTIVATION_DAYS` (365), `JARVIS_LS_RENEW_INFO` (текст «как купить») | НЕТ | `jarvis-license-server init` без ошибок |
| 7 | `init`: база SQLite, стандартные тарифы, файлы `signing.key` и `pepper.key` | НЕТ | команда печатает публичный ключ |
| 8 | **Офлайн-копия** `signing.key` и `pepper.key` (в репозиторий — никогда) | НЕТ | копия лежит вне сервера |
| 9 | `admin-create owner` → токен `jla_…` (показывается один раз) | НЕТ | вход в Jarvis Admin → «Лицензии» |
| 10 | Репозиторий GitHub → Settings → Variables → Actions: `JARVIS_LICENSE_URL` = `https://license.<домен>`, `JARVIS_LICENSE_PUBKEY` = вывод `public-key` | НЕТ | в логе `build-user` нет предупреждения «not set» |
| 11 | Пересобрать Jarvis User (новый запуск CI) и проверить активацию настоящим ключом на Windows (`WINDOWS-CHECK.md`, сценарии 5–8) | НЕТ | сценарии пройдены |
| 12 | Резервные копии: `jarvis-license-server backup …` по расписанию + проверка восстановления | НЕТ | восстановленная копия отвечает `/health` |
| 13 | Платёжный провайдер и выдача ключей продления (в программе оплаты нет) | НЕТ | отдельная работа |
| 14 | Подпись кода Windows для установщиков (иначе SmartScreen предупреждает) | НЕТ | сертификат + шаг подписи в CI |
| 15 | Брандмауэр: наружу открыт только 443; `127.0.0.1:8787` — только прокси | НЕТ | сканирование портов |

## Известные ограничения (не уязвимости сервера, а границы метода)
См. раздел «Что НЕ проверялось / известные границы» в `SECURITY-AUDIT.md`: взлом самой программы, копия виртуальной машины, нет операции «деактивировать» у пользователя, один подписывающий ключ без переходного периода, ограничение подбора ключей опирается на правильный заголовок адреса клиента.

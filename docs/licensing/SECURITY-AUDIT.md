# Jarvis Premium: модель защиты и результаты проверки

Честно: клиентская программа работает на компьютере пользователя, поэтому **абсолютной защиты от взлома нет и не обещается**. Цель — чтобы обычный пользователь не мог получить Premium без сервера, а обход требовал изменения самой программы. Ниже — что сделано, что проверено тестами, а что **не проверялось**.

## Что защищает
| Угроза | Мера | Проверка |
|---|---|---|
| Выдуманный ключ | ключи 140 бит случайности, сервер хранит только HMAC-отпечатки с «перцем» | тест сервера: `unknown_wrong_revoked_suspended_and_late_keys_are_refused`, `full_keys_and_hashes_are_never_in_lists_logs_or_the_database_text` |
| Подбор ключей | ограничения по адресу и общее; ответ одинаков для «нет такого ключа» | `guessing_keys_is_stopped_per_address_and_for_the_whole_server` |
| Один ключ на двух компьютерах | привязка в транзакции SQLite (IMMEDIATE); второй получает отказ | `one_key_one_installation…`, `many_devices_at_once_only_one_wins_even_across_server_processes` |
| Повтор/подделка запроса | подпись установки (Ed25519) на цель + время + ключ; окно 10 минут; повтор подписи отвергается | `a_forged_stale_or_replayed_request_is_refused` |
| Подделанный токен | подпись сервера проверяется ПЕРВОЙ; токен привязан к установке; чужой токен не принимается | тесты клиента `a_token_of_another_installation_or_forged_is_not_believed` |
| «Вечный» Premium без сети | токен живёт до `refresh_by` (72 часа), затем нужна проверка; конец подписки по дате сервера | `the_grace_period_the_clock_and_the_expiry`, `entitlement` (тесты библиотеки) |
| Перевод часов назад | «пол часов» (самый поздний виденный момент) сохраняется в файле; ниже пола — требуется сервер | тест клиента + библиотеки |
| Правка файла состояния | HMAC с ключом из секрета установки; изменённый файл не принимается | `a_hand_edited_state_file_is_dropped` |
| Копия папки на другую учётную запись | секрет установки под защитой Windows (DPAPI) | **не проверено на Windows вручную**; компилируется CI |
| Отозванная/заблокированная лицензия | следующая проверка (каждые 6 ч) убирает токен: Demo | `a_revoked_license_becomes_demo_at_the_next_refresh_and_a_network_loss_changes_nothing` |
| Платная команда любым путём | проверка в `commands::execute_command` (общая точка), в `app.rs` ДО вопроса «подтвердить?», в сценариях и кнопках окна; сломанные правила = платное запрещено | тесты `access`, сборка с `--features user-edition` |
| Новая команда забыта в списке | по умолчанию PREMIUM | `the_embedded_policy_is_valid_and_new_commands_are_premium` |
| Админ-функции у клиента | менеджер лицензий не компилируется в Jarvis User, страница вырезается; в зависимостях нет `server`-признака и серверных пакетов | тест `jarvis_user_gets_a_page_without_the_license_manager`, шаг CI `license-tests`, поиск маркеров в EXE (шаг `build-user`) |
| Секреты в EXE | в клиенте только публичный ключ и адрес; приватный ключ, перец и токены админа не попадают в сборку | шаг CI: поиск маркеров в `jarvis-app.exe` |
| Утечка ключей в логи | ключ в логе — только первая группа (`key_for_log`) | тест сервера на логи |
| Потеря базы при сбое записи | запись в транзакции; при ошибке записи токен не выдаётся | `a_database_that_cannot_write_issues_nothing` |

## Что проверялось на практике (в этой среде)
* Тесты: `jarvis-license` 7, `jarvis-license-server` 19 (включая настоящий HTTP на локальном порту), `jarvis-core` 580 (редакция Admin) и 578 (`user-edition`), в том числе клиент против настоящего сервера в памяти.
* Страница окна (активация, продление, предложение Premium, окончание подписки, менеджер лицензий): снимки экрана в браузере Chromium с имитацией ответов.

## Что НЕ проверялось / известные границы
* **Windows:** DPAPI, окно WebView2, установщик, живой запуск Jarvis User — проверяет только CI-сборка (она компилирует, но не запускает программу) и вы вручную.
* **Реальный сервер:** домен, HTTPS, прокси, резервные копии — не развёрнуты, не проверялись.
* **Оплата:** не реализована (и клиент об этом честно пишет).
* **Взлом самой программы:** кто изменяет `jarvis-app.exe` (убирает проверку, подменяет открытый ключ), получит Premium-команды, которые выполняются локально. Защита от этого — только юридическая и подпись сборок (подпись кода Windows не настроена). Серверной проверки каждой команды нет и быть не может для локальных функций.
* **Копия всей виртуальной машины / образа диска** вместе с сеансом пользователя переносит и секрет DPAPI; ключ при этом остаётся привязанным к одной установке на сервере: вторая копия при проверке получит отказ только если её проверка дойдёт до сервера раньше (до 6 часов + 72 часа).
* Нет операции `deactivate` (освобождение привязки пользователем): привязку сбрасывает администратор.
* Один подписывающий ключ без переходного периода (см. ротацию в DEPLOYMENT.md).

## Как закрепляются голоса (механизм есть, значений пока нет)

В программе есть таблица `VOICE_PINS` (`crates/jarvis-core/src/voice_install.rs`). Запись:
`VoicePin { file: "ru.onnx", revision: "<40 hex: коммит репозитория голосов>", sha256: "<64 hex>", size: <байт> }`.

- Файл с записью скачивается **по коммиту** (`…/resolve/<коммит>/…`, а не из ветки `main`, которая меняется), и принимается только при точном совпадении размера и SHA-256; иначе файл удаляется и не используется.
- Файл без записи скачивается из `main` и проверяется только по форме (размер, не веб-страница, у настроек — JSON с `audio.sample_rate`). В состоянии установки это видно: `voice_pinned: false`, в журнале — «хеш не закреплён». Это **WARN**, а не проверка.
- Неверно оформленная запись (короткий хеш, ветка вместо коммита, чужое имя файла) роняет тест `every_entry_of_the_pin_table_is_well_formed`.

### Как получить значения безопасно
1. Запустите workflow **Voice pins** (`.github/workflows/voice-pins.yml`, ручной запуск, **ничего в репозитории не меняет**). Он берёт текущий коммит репозитория голосов, скачивает каждый файл **именно по этому коммиту** и сверяет байты с тем, что сам репозиторий заявляет для этого коммита (LFS-идентификатор модели, git-идентификатор маленького JSON). Расхождение — ошибка задания. Выход — готовые строки `VoicePin {…}`.
   - Ограничение GitHub: ручной запуск доступен, когда файл workflow есть в основной ветке. Пока он только в ветке разработки, запустить его можно только после согласованного слияния; без этого значения получить нельзя, и они не вносятся.
2. Не принимайте вывод на веру: сравните коммит и хеши с независимой копией (страница файла на этом коммите, повторная загрузка из другой сети) — совпадение с тем же сервером, откуда пришёл файл, не независимо.
3. Только после этого человек вносит строки в `VOICE_PINS` отдельным коммитом. Значение, которое подтвердить нельзя, не вносится.

### Обновление модели независимо от программы
Новая версия голоса = новый коммит репозитория + новые значения в таблице. Старая запись не меняется «по месту» без нового коммита программы: так версия и хеш всегда идут вместе и проверяются тестом.

## Модель угроз (кратко)

- Другой пользователь Windows: папка данных закрыта защищённым списком доступа (`acl.rs`), файлы секретов наследуют его.
- Сторонний процесс того же пользователя: не останавливается — он владелец папки и может читать файл токена, память Jarvis и подменять файлы пользователя.
- Администратор и SYSTEM: не останавливаются.
- Подмена файла или архива в сети: HTTPS + закреплённый хеш там, где он есть (см. таблицу).

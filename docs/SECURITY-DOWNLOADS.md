## Как закрепить хеш голоса (безопасный порядок)

1. В логе сборки CI (`Build Windows installer` → шаг «Add Piper neural voices») печатаются строки `VOICE PIN CANDIDATE (unverified)` — это **кандидаты**, а не проверка.
2. Откройте страницу файла на huggingface.co (вкладка Files → файл → «Copy SHA256» у LFS-файла) и сравните значение с этой страницы с кандидатом **в браузере, под своей учётной записью**. Значение со страницы того же сервера, что и файл, — не независимое доказательство; лучше сравнить ещё с копией из другого источника или проверить подпись коммита.
3. Закрепите ревизию (URL вида `resolve/<хеш-коммита>/…` вместо `main`) и впишите пары в `VOICE_PINS` (`crates/jarvis-core/src/voice_install.rs`). Пока таблица пуста, программа честно пишет в журнал «хеш не закреплён».
4. Хеш не выдумывается: значение, которое нельзя подтвердить, в таблицу не вносится.

## Модель угроз (кратко)

- Другой пользователь Windows: папка данных закрыта защищённым списком доступа (`acl.rs`), файлы секретов наследуют его.
- Сторонний процесс того же пользователя: не останавливается — он владелец папки и может читать файл токена, память Jarvis и подменять файлы пользователя.
- Администратор и SYSTEM: не останавливаются.
- Подмена файла или архива в сети: HTTPS + закреплённый хеш там, где он есть (см. таблицу).

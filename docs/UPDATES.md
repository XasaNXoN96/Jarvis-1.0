# Обновления программы

Обновление — это три кнопки в **Настройки → Общие → Обновления**: «Проверить обновления» → «Скачать» → «Установить и перезапустить».
Само ничего не скачивается и не устанавливается, кроме проверки по кнопке.

## Как это защищено
- Программа знает только **публичный ключ владельца** (`JARVIS_UPDATE_PUBKEY`) и **адрес списка** (`JARVIS_UPDATE_URL`, https). Они вшиваются при сборке Jarvis User.
- Список `update.json` подписывает владелец на своём компьютере. Подпись покрывает версию, адрес установщика, его SHA-256 и размер.
- Программа ставит файл только если: подпись подходит, адрес https, размер и SHA-256 скачанного файла совпали с подписанными, версия новее текущей. Перед запуском файл проверяется ещё раз.
- Секретный ключ обновлений **не** в репозитории, **не** в сборке и **не** на сервере лицензий. Это отдельный ключ.

## Что сделать владельцу (один раз)
1. Создать пару ключей: `jarvis-license-server update-keygen update-signing.key`. Файл `update-signing.key` хранить офлайн и сделать копию. Команда печатает публичный ключ.
2. В настройках репозитория GitHub (Settings → Secrets and variables → Actions → Variables) добавить `JARVIS_UPDATE_PUBKEY` (этот публичный ключ) и `JARVIS_UPDATE_URL` (например `https://example.com/jarvis/update.json`).
3. Собрать Jarvis User заново (без этих двух значений кнопка пишет «обновления не настроены»).

## Как выпустить обновление
1. Поднять `version` в корневом `Cargo.toml` (`[workspace.package]`) и в `installer/jarvis.iss` (`AppVersion`), собрать установщик `Jarvis-User-Setup.exe`.
2. Загрузить установщик на свой https-сервер.
3. Подписать: `jarvis-license-server update-sign update-signing.key Jarvis-User-Setup.exe 0.2.0 https://example.com/jarvis/Jarvis-User-Setup.exe "Что нового"` — команда печатает готовый `update.json`.
4. Положить `update.json` по адресу `JARVIS_UPDATE_URL`.

## Что не проверено
Работа на реальном Windows (запуск установщика с правами, закрытие и повторный запуск программы) и на реальном сервере не проверялась: тесты покрывают подпись, сравнение версий, размер и SHA-256, неверные и небезопасные списки.

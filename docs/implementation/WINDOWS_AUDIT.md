# Этап 2: аудит Windows-приложения

Начальный коммит этапа: `bdc1fe2`. Физический ПК с Windows не использовался. Всё ниже проверено: автотестами (Linux, обе редакции), `cargo check` и `--tests` под `x86_64-pc-windows-gnu`, Windows CI, а страницы — в Chromium с имитацией сервера. Реальный WebView2 не открывался.

## Что проверено чем

| Вид проверки | Что покрывает | Чего не покрывает |
|---|---|---|
| Unit-тесты (`cargo test -p jarvis-core`, обе редакции) | чистая логика: статусы winget, наблюдатель микрофона, журналы, фильтры, память/заметки/отмена, сессии игр, монитор | реальные вызовы Windows (winget, ShellExecute, NVML, микрофон) |
| Windows-компиляция (`--target x86_64-pc-windows-gnu`, `--tests`) | что код Windows-ветвей собирается | запуск |
| Windows CI (`build-windows.yml`) | тесты на Windows, сборка Admin/User/DirectML, лицензии | `gui-check` (jarvis-gui, информационный) красный и раньше |
| Chromium (`tests/ui/*.js`, `ui-check.yml`) | вёрстка страницы при 100/125/150/200 % масштабе и размерах 700–1920 px, журнал безопасности, отмена удаления | WebView2, настоящие шрифты и DPI Windows |
| Физический ПК / микрофон / игра / API-ключ | — ничего не выполнялось | см. раздел «Только владелец» |

## Игровой режим: что проверено автоматически, что нет

Автоматически: профили, фразы, ограничения (только окно игры на переднем плане, остановка при анти-чите, ограничение прицела), список игр и запуск по ID, статистика сессий (теперь и со сном). Игровой режим не держит постоянной нагрузки: трекер статистики спит, пока игры нет на переднем плане. Режим не выключается сам, когда игра закрыта: он просто не действует вне окна игры (клавиши отпускаются). Не проверялось: запуск Steam/Epic/GOG, голосовые команды внутри игры, вылет игры, прицел — всё это требует реальной игры.

## Только владелец (физический ПК, микрофон, игра, ключ ИИ)

1. **winget:** на ПК с winget — найти и установить небольшую программу, отменить установку на середине (ожидание: статус «Отменено» только когда процесс остановлен), отключить сеть во время загрузки (ожидание: «Ошибка», не «Готово»).
2. **Микрофон:** выдернуть USB-микрофон на 30 с и вернуть (ожидание: в «Диагностика → события» появятся «Микрофон: звук не приходит…», «переоткрываю…», «звук идёт»); заблокировать Windows/усыпить ПК и разбудить; открыть микрофон в другой программе в монопольном режиме. Фраза «Джарвис» голосом (шум, расстояние).
3. **Собственный голос:** Jarvis не должен реагировать на свою озвучку; стоп-слово во время речи.
4. **Игра:** запустить игру из списка (Steam/Epic/GOG), включить режим, сказать команду, закрыть игру/«убить» процесс; усыпить ПК в игре (сессия должна закончиться на моменте сна).
5. **ИИ:** реальный ключ OpenAI-совместимого API и Gemini: неверный ключ, лимит, обрыв сети посреди ответа, кнопка «Стоп».
6. **Монитор:** NVIDIA — температура/частота/VRAM; монитор с частотой 144 Гц — «Частота экрана»; встроенная графика AMD/Intel — «Недоступно».
7. **Интерфейс (WebView2):** масштабы Windows 100/125/150/200 %, перетаскивание границ окна, Tab-навигация по журналу безопасности и настройкам.
8. **Сообщить об ошибке:** Диагностика → «Копировать диагностический отчёт» (без ключей и паролей) и описать шаги.

## Не сделано в этапе (остаётся)
- Реальная проверка WebView2, физического микрофона, игры, winget и ключей ИИ.
- Корреляция номера операции для событий диагностики (кроме журнала безопасности).
- Сохранение текущей игровой сессии при закрытии Jarvis.
- Страница «Игры»/«Команды»/карточки программ проверены только на отсутствие горизонтального переполнения; не прогонялись сценарии «ярлык удалён», «скрытие карточки» в браузере (покрыто unit-тестами `proglib`).

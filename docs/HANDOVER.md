## 2. Как устроена обработка фразы (аудит, на что опираться)

* Все фразы идут как `origin::Incoming {text, source, via_script}`. Единственный способ поставить фразу в очередь — `remote::submit(source, text)`. Двери `Source`: `Voice, Window, Phone, Telegram, Console, Ipc, Script, Internal`; `Source::is_remote()` = Phone/Telegram. Дверь НЕ доказывает личность.
* `crates/jarvis-app/src/app.rs::execute_command(text, source, rt)` — порядок: подтверждение (`confirm.rs`, ответ «да/нет» только с той же двери, TTL 30 с, одноразовое) → открытые **сессии** (`session.rs`: диктовка, вопрос о файле, выбор программы, режим «Работа с объектом» `kind == "object"`, режим чата) → **`codeobj::handle`** (новое) → сценарии «Конструктора» → программы по имени → слово-триггеры → интент-классификатор → ИИ-вопросы (`route.rs`) .
* `policy.rs`: уровни риска Low/Medium/High у команд; операции `Op {Shell, Run, Open, FsWrite, FsRemove, FsRead, Keys, Input}`; `judge/authorize`; allowlist программ; защищённые корни; запись только в папки пользователя (Документы, Рабочий стол, Загрузки, Изображения, Музыка, Видео) и временную; папка данных Jarvis для команд закрыта. Операция выше риска команды отклоняется; High требует подтверждения (`confirm.rs`).
* `safefs.rs`: файловые операции Lua/Rust через дескрипторы с двойной проверкой политики (`write`, `append`, `remove`, `mkdir_all`, `read`, **`create_new`** — новая, не перезаписывает). Тестовый хук `set_between`.
* `psrun.rs`: **единственная воронка PowerShell** — enum `Script` (постоянные тексты, проверенные переменные окружения), `lint` запрещённых шаблонов, закрывает stdin; статический тест запрещает PowerShell вне воронки. Любая новая автоматизация Office/PowerShell — только через новый `Script` там.
* Lua-песочница: нет `io/package/require/debug/os` опасных, `jarvis.system.exec` отказывает, `jarvis.fs.*` через `safefs`; типы команд lua/ahk/cli/voice/terminate/stop_chaining. `integrity.rs` + `build.rs`: встроенный SHA-256 манифест команд (непроверенные → песочница Standard; только в CI-сборках с `BUILD_SHA`). **Изменение любого файла в `resources/commands` меняет манифест** — это нормально, пересобирается в CI.
* ИИ: `ai.rs` (провайдеры Gemini/OpenAI/Anthropic-типа, потоковый ответ, `AiError`, чат-хранилище). Для Lua доступны только `jarvis.ai.screen` и `jarvis.ai.ready`; генерация текста для объектов идёт из Rust (`ai::complete`, добавлено в этом сеансе).
* Озвучка Piper/Windows SAPI: `tts.rs`; распознавание Vosk; микрофон pvrecorder (DLL проверяется по SHA-256).

## 4. Этот сеанс: Object Interaction Engine («голосом работать с объектами»)

Задача владельца: реальная интеграция в существующий Jarvis (не демо): машина состояний, контекст объекта, Стоп/Пауза/Отмена/Продолжим, адаптеры Word/Блокнот/VS Code (+Excel, PowerPoint, Проводник, браузер, Telegram, медиа — последние НЕ сделаны).

### 4.1 Модуль `objects.rs` (ядро) — коммит `74c2f2f`
* **Состояния:** `IDLE, APP_OPEN, OBJECT_ACTIVE, DICTATION, AI_TASK, AWAITING_CONFIRMATION, PAUSED, ERROR_RECOVERY`. Функция `next(from, event)` — единственная таблица разрешённых переходов; остальное → `Forbidden`. Тесты проверяют каждый переход, запреты (нельзя диктовать во время генерации, второй вопрос, «да» без вопроса, второй ИИ-запрос…), отсутствие «зависших» состояний.
* **Контекст:** id, вид (`word_doc, excel_book, text_file, code_file, presentation, folder, browser_page`), программа, имя, путь, проект, способ проверки окна (`Detect`), режим, операция, ожидающий вопрос, статус ИИ (`none/running/done/cancelled/failed`), короткая история (8 сообщений ≤240 символов, **секреты скрываются** `sanitize`), результаты (5), факт подтверждённого сохранения (`saved_confirmed`, сбрасывается `changed()`).
* **Задача ИИ:** `start_ai` выдаёт номер и флаг отмены `Arc<AtomicBool>`; `ai_finished(task, result)` принимает результат **только** если задача текущая и не отменена — поздний ответ после «Стоп» отбрасывается; результат старой задачи не принимается новой.
* **Стоп/Пауза/Отмена:** `stop()` — завершает диктовку, отменяет генерацию, снимает вопрос, ставит `PAUSED`, сохраняет объект (программа и документ НЕ закрываются), `resume_prompted` → «Продолжим?»; `pause()` — то же без вопроса; `cancel()` — только текущая операция, объект остаётся активным; `finish()` — завершить работу с объектом из любого состояния; `lost()/app_closed()` → `ERROR_RECOVERY`; `resume()` только после проверки адаптером.
* **Классификатор слов** `classify(text, state)`: «стоп/остановись/хватит/прекрати ввод/пока остановись/не закрывай просто остановись», «пауза», «отмена», «продолжим с объектом/продолжай с этим файлом/вернись к документу/продолжай писать код/возобнови работу», «да/нет». **Внутри диктовки команда только если это ВСЯ фраза**; «он сказал стоп и ушёл», «на светофоре знак стоп», «хватит ли нам времени» — текст. «отмени последнее действие» остаётся командой Word (undo), не отменой операции. В `IDLE` слова не принимаются; глобальное «стоп» (останавливает озвучку, команда `stop_1`) не перехватывается, если ничего не запущено.
* **Проверка окна** `Probe`/`verify` (процесс + заголовок), `SysProbe` (реальная на Windows через `input::front_info`, на других ОС «ничего не запущено»).
* Общий процессный движок `objects::with(|e| …)`, `snapshot()` для UI.

### 4.2 Интеграция в Lua (`office.lua`, `program.lua`, `command.toml`)
* Новое `jarvis.object.*` API (`lua/api/core.rs`): `state, open_app, bind, dictation, stop, classify, resume, decline_resume, lost, app_closed, recovered, finish, release, reset, ask, answer, saved, changed, note, info`, и `doc_ai, doc_ai_peek, doc_ai_drop, text_hash, b64_contains`.
* Шаги диалога синхронизированы с автоматом (`eng_sync`): диктовка только в шаге `typing`; вопросы `overwrite`, `confirm_delete`, `confirm_replace` → `AWAITING_CONFIRMATION`.
* **Стоп** в диктовке → пауза (раньше «стоп» вёл в вопрос сохранить/удалить; теперь «Заканчиваем работу с объектом» ведёт туда, «стоп» — пауза). Сессия `object_resume` ждёт «да/нет». Команда `assistant_object_resume` («продолжим с объектом…»). При продолжении проверяются: программа открыта, документ тот же (другой активный документ → остаёмся на паузе, **в другой документ не пишем**), документ открыт (закрыт → `ERROR_RECOVERY` + предложение открыть заново по сохранённому пути).
* Потеря объекта во время диктовки (`NOAPP/NODOC`) → сообщение, текст нигде не печатается.
* «Открой VS Code/Word/…» → `jarvis.object.open_app(id)` после подтверждения запуска процесса (`program.lua`).
* Сохранение: `jarvis.object.saved(path)` только после успешного ответа адаптера.

### 4.3 `docai.rs` — ИИ над текстом Word — коммит `4fafa2c`
Задачи: исправить ошибки, официальный стиль, перевод (язык называется), сократить, вступление, объявление. Только **короткая фраза целиком** (≤9 слов) — длинное предложение это диктовка. Поток: Lua читает текст документа (`office.ps1 word/read`, Base64) → Rust `docai::start` (проверка размера ≤40 000 символов, **проверка секретов**, ИИ готов?) → поток с `ai::complete` и флагом отмены → результат лежит в памяти, внутренняя фраза `objaidone` (константа `DONE_MARKER`) сообщает диалогу → Lua: вставка (вступление/объявление) с **проверкой чтением** или вопрос «Заменить?» (замена всего текста). Замена `word/replace` выполняется **только если хеш текущего текста документа равен хешу, который читал ИИ** (иначе «текст изменился, ничего не заменено»), после замены хеш проверяется. Нормализация текста идентична в `office.ps1` (`Norm-Text`, `Text-Hash`), `docai.rs` (`normalize`, `text_hash`) и `fake_office.py`. «Стоп» во время «Работаю над текстом» отменяет задачу, ответ отбрасывается, во время работы реплики **не печатаются** в документ. Фраза `objaidone` не пишется в «Диалоги» (исключение в `app.rs`), есть и команда `assistant_object_ai_done`.
* **Автозамена Word** при проверке вставки (`docai::fold`): типографские кавычки/тире/многоточие/неразрывные пробелы приводятся к простым с обеих сторон; любое другое расхождение — ошибка (тесты в обе стороны).

### 4.4 `codeobj.rs` — VS Code + Python — коммит `f77508f`
Пользовательский сценарий: «Открой VS Code» → «Создай Python-файл» → имя («назови calculator.py», кириллица транслитерируется; «точка пи вай») → если нет проекта, спрашивает папку («документы / рабочий стол / загрузки», «папка …») → файл создаётся `safefs::create_new` (существующий **не** перезаписывается — работает с ним, ничего не меняя), открывается в VS Code (`Code.exe` найден через `apps::locate`, путь не берётся из речи) → «Напиши калькулятор на Python» (ИИ, `ai::complete`, не пишет в диалоги) → код записывается самим Jarvis (не печатается в окно) и **проверяется чтением**; потом `ast.parse` (Python найден по PATH, заглушка WindowsApps игнорируется, `python -I -B -X utf8 -c …`; **парсит, но не запускает**) → «Добавь обработку деления на ноль» (правка текущего файла: ИИ получает текущее содержимое; запись только если файл не менялся с момента чтения; **большое изменение** — много удалённых строк — ждёт «да»; хранится предыдущая версия → «верни как было» с проверкой, что файл не менялся после записи) → «Стоп» (отмена генерации, пауза) → «Продолжим с объектом» (проверяются: VS Code запущен, файл существует, изменён ли он вне Jarvis — перечитывается).
Другое: «создай проект …», `requirements.txt`, `README.md`, тесты (`test_<имя>.py`); «объясни ошибку/код» (ответ показывается, ничего не пишется); «проверь синтаксис»; «повтори генерацию» (запрос сохраняется при недоступности ИИ); **«запусти код/файл» — отказ** («сгенерированный код не запускается автоматически»).
Безопасность: файл или запрос с ключом/паролем (`contains_secret`) в ИИ не отправляются; файл >256 КБ и не UTF-8 не трогаются; **принимаются только двери Voice/Window/Console** (Phone/Telegram/Ipc/Script/Internal — нет; найдено и исправлено в стабилизации — коммит `034297f`). Перехватывает «стоп/отмена» только когда реально идёт ИИ-задача или вопрос; в покое слова остаются обычными командами. Обычное «напиши калькулятор на Python» без объекта по-прежнему идёт в ИИ-чат.

### 4.5 UI — часть `74c2f2f`

## 7. Технические детали и подводные камни

* **Тесты:** `cargo test -p jarvis-core --no-default-features --features lua_only` (≈45 с; в среде команда может упереться в лимит 120 с — запускать в фоне). Все тесты используют **глобальное состояние** (`session`, `objects`, `appindex::PENDING`, `remote::RUNNING/OUTBOX`, `dialog`). Замки: `session::TEST_LOCK` (сессия/движок/Lua-сценарии), `appindex::TEST_LOCK`, `remote::PHONE_TEST_LOCK`, `uistate::TEST_LOCK`, `objects::TEST_LOCK`. Тесты политики используют **thread-local** места (`policy::set_test_allowed`); для рабочего потока теста есть `test_places()/apply_test_places()` (используется в `codeobj`/`docai`).
* **Тестовые хуки только под `cfg(test)`:** `codeobj::GENERATOR` (подставной ИИ), `PROBE`, `LAUNCH`, `PLACES_ROOT`; в `policy.rs` `JARVIS_TEST_RUNNER` (поддельный Office).
* **Windows-проверка типов без Windows:** `cargo check -p jarvis-core --no-default-features --features lua_only --target x86_64-pc-windows-gnu`. `jarvis-app` локально не собирается под этот таргет (нет prebuilt ort-sys) — его `app.rs` проверяется только в CI; поэтому правки `app.rs` делать аккуратно.
* **Lua-тесты** (`lua/object_tests.rs`, `lua/tests.rs`) запускают настоящие скрипты против `fake_office.py` (Python). Флаги поддельного Word: `autocorrect`, `corrupt`. Фраза в тесте произносится в нижнем регистре, как в приложении.
* **`psrun`/Office:** любые новые действия `office.ps1` — через существующий `ps_file`; не добавлять сырой PowerShell. Новые действия добавлены: `word/read`, `word/replace`.
* Файл **`office.lua` большой** (~1300 строк): блоки — вспомогательные, диктовка, `file_session`, режим объекта (`obj_*`), стоп/пауза/продолжение, ИИ над текстом (`doc_ai_*`, `obj_ai_done`, `obj_replace_answer`), сохранение, точки входа по `id` команды. Тип сессии `object` с шагами `typing, ask_end, save_name, overwrite, confirm_delete, doc_ask, doc_name, app_ask, ai, confirm_replace`; `object_resume` с данными `ask/reopen/gone`.
* Триггеры команд — это **основы слов** (`"продолж объект"` совпадает по префиксам, порядок не важен); добавляя триггеры, проверять конфликты (`fetch_by_triggers` выбирает самый специфичный).
* CI: артефакты (`dist` = установщики, `jarvis-app`) в запуске; скачивание — только владельцу при входе. Не обновлять `build-latest`.
* Среда сессии: `ToolSearch` нужен для `mcp__github__*`; напоминания через `send_later`; фоновые прогоны — `run_in_background` + Monitor (нельзя `sleep`).
